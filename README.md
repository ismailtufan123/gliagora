# Gliagora | Neuroscience

Where neuroscience meets. Source for [gliagora.com](https://gliagora.com): a curated, English-first neuroscience hub.

- Plan and decisions: [`PLAN.md`](PLAN.md)
- Conventions for contributors and Claude Code: [`CLAUDE.md`](CLAUDE.md)

## Stack

One TypeScript app: Next.js (App Router) with Payload CMS 3 inside it, on PostgreSQL.

| Path                      | What it is                                                      |
| ------------------------- | --------------------------------------------------------------- |
| `src/app/(frontend)/`     | Public site, one folder per locale: `en/` (`/en/`, `/en/contact/`), `tr/` (`/tr/iletisim/`) |
| `src/app/global-not-found.tsx` | The 404 page for unknown public URLs (not /admin, /api) |
| `src/proxy.ts`, `src/lib/gone.ts` | 410 Gone for removed URLs (PLAN §2.5)                 |
| `messages/`               | All user-visible text, per locale (`en.json`, `tr.json`)        |
| `content/`                | Long-form pages in Markdown (About, legal texts); see `src/lib/content.ts` |
| `src/i18n/`               | Locale settings for next-intl                                   |
| `src/app/(frontend)/tokens.css` | Design tokens (PLAN §7): colours, type, spacing, motion   |
| `src/components/`         | Shared React components; `header/` holds the header, menus and language switcher |
| `src/lib/site.ts`, `src/lib/navigation.ts` | Paths, windows, sections and mega-menu entries |
| `src/fonts/`              | Self-hosted WOFF2 fonts and their licences (`tools/fonts/`)     |
| `public/brand/`           | Logo files and favicon                                          |
| `src/app/(payload)/`      | Payload admin (`/admin`) and API (`/api`); generated by Payload |
| `src/collections/`        | Payload collections (the data model)                            |
| `src/migrations/`         | Database migrations, generated by Payload and committed         |
| `src/payload.config.ts`   | Payload configuration                                           |
| `src/payload-types.ts`    | TypeScript types generated from the collections                 |
| `compose.yaml`            | Local PostgreSQL for development                                |
| `Dockerfile`              | Production image (built in CI, pulled by the server)            |
| `.github/workflows/ci.yml` | CI: checks, image build, smoke test, push to GHCR              |
| `deploy/`                 | Production server: setup script, Compose, Caddy ([runbook](deploy/README.md)) |

## Local development

You need Node.js 24 (LTS; see `.nvmrc`), Docker, and pnpm through Corepack.

```sh
corepack enable                 # makes the pnpm version in package.json available
pnpm install
cp .env.example .env            # then replace the placeholders (see comments in the file)
docker compose up -d db         # start PostgreSQL on 127.0.0.1:5432
pnpm migrate                    # create or update the database tables
pnpm dev                        # http://localhost:3000 (redirects to /en/)
```

The admin panel is at http://localhost:3000/admin. On an empty database it asks you to create the
first admin account: use a made-up address such as `editor@example.com`. Local data is fake data
only.

To stop the database: `docker compose stop db`. To delete it with all local data:
`docker compose down -v`.

## Checks

```sh
pnpm lint        # ESLint and Prettier (fix formatting with `pnpm format`)
pnpm typecheck   # TypeScript
pnpm test        # Vitest unit tests
pnpm test:e2e    # Playwright + axe end-to-end tests (needs the app running, see below)
```

The end-to-end tests (`tests/e2e/`) open every public template in light and dark mode, on desktop
and mobile. They fail on any serious or critical axe issue or any request to another domain. They
also check keyboard paths and HTTP behaviour. Run them against a production build:
`pnpm build && pnpm start` with the database up, then `pnpm test:e2e` in a second terminal. The first
time, install the browser with `pnpm exec playwright install chromium`. List every new page template
in `tests/e2e/pages.ts`.

## CI and the Docker image

Every pull request and every push to `main` runs `.github/workflows/ci.yml`:

1. `pnpm lint`, `pnpm typecheck` and `pnpm test`.
2. Builds the Docker image and starts it against an empty PostgreSQL 18 (smoke test): migrations
   must apply, `/health/` must answer `ok` and the pages must render. Then the end-to-end tests
   (`pnpm test:e2e`) run against that container.
3. On `main` only: pushes the image to `ghcr.io/ismailtufan123/gliagora` with the tags `main` and
   `sha-<commit>`.

The image applies pending migrations when it starts (`src/lib/startup.ts`). If the database is
unreachable or a migration fails, it exits and Docker restarts it. `/health/` returns 200 when the
database is reachable.

To build and run the image locally: `docker build -t gliagora .`, then run it with `DATABASE_URL`,
`PAYLOAD_SECRET` and `ALTCHA_HMAC_KEY` set (without the last, the suggestion form says it is
temporarily unavailable).

## Changing the data model

The database schema only changes through committed migrations (PLAN §20).

1. Edit or add a collection in `src/collections/` and register it in `src/payload.config.ts`.
2. `pnpm migrate:create <short-name>` writes a migration to `src/migrations/`.
3. `pnpm migrate` applies it to your local database.
4. `pnpm generate:types` updates `src/payload-types.ts`.
5. Commit the collection, the migration and the types together.

If you add custom admin components, run `pnpm generate:importmap`.
