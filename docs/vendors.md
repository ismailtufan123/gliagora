# External services

Every service outside our server that Gliagora uses, what it sees and where it is (PLAN §18.2, "Vendor control"). Adding one needs a KVKK check first and an entry here. Visitors' pages load nothing from another domain: pages, fonts, the map's tiles, fonts and sprites all come from `gliagora.com` (checked by the end-to-end tests and at S). The one exception is a member's own choice: "Continue with Google" or "Continue with ORCID" takes that browser to Google's or ORCID's own sign-in page and back (M4b).

| Service | What for | What it sees | Where | Personal data |
| --- | --- | --- | --- | --- |
| Hosting Türkiye | The server (VDS, Istanbul), since S | Everything on the server | Türkiye | Yes: hosts all of it (processor, KVKK Art. 12) |
| Cloudflare | Domain registrar and DNS (DNS only, D1); Email Routing for `hello@` until M2 (D2, §11.4) | DNS: the domain's records and the lookups of visitors' resolvers. Email Routing: incoming mail to `hello@` | Abroad | Email Routing: yes, until it is switched off at M2 |
| GitHub | Code, CI (Actions), container registry (GHCR), the Deploy workflow | Code, test runs with fake data, images | Abroad | No (code only; never personal data, CLAUDE.md) |
| Let's Encrypt | TLS certificates (Caddy) | The domain names | Abroad | No |
| Docker Hub | The Caddy and PostgreSQL images (pinned by digest) | The server's IP address | Abroad | No |
| Ubuntu and Docker package archives | Updates of the server | The server's IP address | Abroad | No |
| Google Public DNS (8.8.8.8) | The server's DNS resolver (set by the provider's cloud-init) | The names the server looks up (the services in this table), never anything a visitor typed | Abroad | No |
| ROR (`api.ror.org`) and Zenodo | Institutions: the nightly check for a new ROR release, the monthly import, and editors adding one by its ROR ID | The server's IP address and the ROR IDs editors enter | Abroad | No |
| Protomaps builds (`build.protomaps.com`, `build-metadata.protomaps.dev`) | The map's basemap (OpenStreetMap data), downloaded to our server by `deploy/basemap/fetch-basemap.sh` about twice a year (M5, PLAN §14) | The server's IP address | Abroad | No |
| Google (`accounts.google.com`, `oauth2.googleapis.com`, `www.googleapis.com`) | "Sign in with Google" for members who choose it (M4b, D49): a service the member deals with directly, under Google's own terms | On Google's page: whatever the member does there, with their own Google account; Google learns that the member signs in to Gliagora. From our server: our client ID and secret, the one-time code and our redirect address (`/en/sign-in/google/callback/`), when it exchanges the code for an ID token, and requests for Google's discovery document and signing keys. We send Google nothing about the member: no address, no name, no hint | Abroad | We send none. Google sends us the account's ID, its email address and whether it is verified (and a Workspace domain); we keep the ID, and the address only if Google manages it (Gmail or Workspace) |
| ORCID (`orcid.org`) | "Sign in with ORCID" for members who choose it (M4b, D49): a service the member deals with directly, under ORCID's own terms (the free Public API) | On ORCID's page: whatever the member does there, with their own ORCID record; ORCID learns that the member signs in to Gliagora. From our server: our client ID and secret, the one-time code and our redirect address (`/en/sign-in/orcid/callback/`), and requests for ORCID's discovery document and signing keys. We send ORCID nothing about the member | Abroad | We send none. ORCID sends us the member's ORCID iD and the name on the record; we keep the iD, and the name only if the member chooses to |
| GitHub (`protomaps/go-pmtiles`, `protomaps/basemaps-assets`) | The pmtiles tool, and the map's fonts (SIL OFL) and sprites (MIT), each pinned and checked, fetched by the same script | The server's IP address | Abroad | No |

| Employers' own websites (the sources, M7, D52) | The monitors: reading the vacancy lists, feeds and documented job APIs of the employers in `sources` once a day, and the weekly link check of published jobs' original pages | The server's IP address and the monitor's user agent (`Gliagora-Monitor/1.0`, with a link to the About page) | Worldwide | We send none. The pages can name people (a lab's head, a contact); names, email addresses and phone numbers are removed before a posting's text is stored |
| Anthropic (Claude Code; the Claude API) | AI drafts of candidates (M7, D52; PLAN §6.6): once a week through Claude Code on the operator's computer; the Claude API from the server, off until a key and a monthly cap are set | The candidates' text with names, email addresses and phone numbers replaced, the facts the monitors read and the institution: never a posting's address, a note or anything about members | Abroad | Redacted text only; a name can slip through the rules (the accepted risk of PLAN §15.2, flag 6; lawyer question B17) |

At M2 the Turkish mailbox (its SMTP server sends the newsletter and the forms' emails) joins this table, and Cloudflare Email Routing leaves it.
